Atomic State Commits

Tactical Adoption Playbook & Recommendations

Best practices derived from our evaluation across both project paradigms.

★

Greenfield Project Workflow

Creating new applications from scratch

1. Initialize with Automated Gates

Pass --auto to bypass spec and plan confirmation prompts:

npx fabrica-skills@latest init-run --name my-app --auto
2. Leverage Sensible Defaults

When prompted by /fab-spec, leave stack slots blank unless you have strict constraints; it will pick Vite+React, FastAPI/Express, and SQLite automatically.

3. Respect Per-Axis Quality Thresholds

If a stage receives an eval score under 6, run /fab-fix <stage> before integrating. The state machine strictly blocks incomplete stages.

🛡

Legacy Codebase Workflow

Adopting into existing production repositories

1. Ensure Clean Git Baseline First

Commit or stash all existing work before running init-existing-run. Fabrica captures your exact HEAD commit and requires a clean working tree.

2. Add Fabrica Artifacts to .gitignore

Prevent untracked harness skills from marking the repo dirty:

echo -e ".agents/\n.claude/\n.cursor/\nfabrica.run.json\ndocs/fabrica/" >> .gitignore
3. Define Strict Allowed Change Paths

During /fab-plan, ensure allowed_change_paths contains only the specific directories (e.g. src/modules/billing/**) you intend to touch.

Final Verdict & Recommendation

fabrica-skills is highly recommended for software engineering teams adopting AI coding assistants systematically. It successfully bridges the gap between unconstrained greenfield velocity and high-stakes legacy risk mitigation without requiring any proprietary runtime services or vendor lock-in.
