Key Architectural Innovations in fabrica-skills

1. Non-Intrusive Projection

Instead of forcing users to adopt a proprietary runtime daemon, it projects markdown skill files directly into agent discovery folders (.agents, .claude, etc.). Zero dependencies added to app package.json.

2. Immutable Gate Hardening

The --auto flag gives power users speed while preventing catastrophic mistakes. Skills like /fab-verify and /fab-decide are strictly prohibited from running unattended.

3. Vertical Slicing Rigor

Forces the agent to implement one named slice at a time against docs/blueprint.md, evaluating quality scores (must be ≥ 6/10) before integration, drastically reducing hallucinations.

Practical Recommendations for Users

01
Run with an agent that has bash execution: Because the skills rely on invoking commands like node scripts/validate-run.mjs, ensure your agent harness (such as Claude Code, OpenCode, Cursor Agent) has tool access enabled.
02
Use --auto for rapid prototyping, omit for production: If you are testing an exploratory idea, npx fabrica-skills init-run --auto saves time by removing prompt friction on spec, plan, and wire stages while keeping the final verification gate safe.
03
Maintain fabrica.run.json in version control: Commit fabrica.run.json and docs/ along with your repository to preserve the audit trail of decisions, verifications, and quality scores.
